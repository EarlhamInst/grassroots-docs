# Service description

## Requesting the service description

Each service is dynamically-generated by the Grassroots backend server. To request the definition of a service, a JSON request is sent to the server with the following format:

```
{
  "header": {
    "schema": {
      "so:softwareVersion": "0.10"
    }
  },
  "@context": {
    "so:": "http://schema.org/",
    "eo:": "http://edamontology.org/",
    "efo:": "http://www.ebi.ac.uk/efo/",
    "swo:": "http://www.ebi.ac.uk/swo/"
  },
  "operations": {
    "operation": "get_named_service"
  },
  "services": [
    {
      "so:name": <SERVICE NAME>
      
      <OR>

      "so:alternateName": <SERVICE ALTERNATE NAME>
    }
  ]
}


```

In the `services` array above, you can specify multiple services by either their standard or alternate names.
The standard names are the human-friendly names with spaces _e.g._ _Submit Field Trial Programme_. The alternate names are more machine friendly and don't contain spaces such as _field\_trial-submit\_programme_.

## Parameter Set

The parameters for the service are described in the `services.operation.parameter_set` section.

### Level

The initial key is `level` which specifies the default _parameter level_ for each of the parameters if one is not explicitly specified. This level allows user to choose different sets of parameters dependent on their expertise. The levels are

  * **all**:
  * **advanced**: 
  * **simple**: 
  * **wizard**:

The parameters are specified in the array given by the `parameters` key. This contains an array of objects where each one gives the details for a single parameter.
